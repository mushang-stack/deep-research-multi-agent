# PRD · 深度研究助手 v2.0(产品化)

> 版本 v2.0 · 状态 Draft · 2026-08-25 · 作者:王宇博
> 前序:MVP(deep-research-multi-agent)已完成并验证,工程详报见[项目详报](PROJECT_REPORT.md)

## 1. 定位

一句话:面向知识工作者的深度研究助手——输入一个研究问题,产出**每条结论都带引用、可点开溯源验证**的研究报告。差异化押「可信度」,不押「快」。

## 2. 背景与机会

- **痛点**:知识工作者(行研/咨询/投研)写对比类、综述类报告,人工检索整理动辄半天;LLM 直接问答有幻觉,不敢直接交付;通用 AI 搜索(Perplexity / 秘塔类)面向快速问答——快而浅、结论不可溯源,对要交付报告的人不够用。
- **MVP 已验证技术可行性**(真实跑分,见[项目详报](PROJECT_REPORT.md)):
  - Grounding **0.932**(上线门槛 0.85,passed)
  - 多 agent vs 单 agent 基线:Grounding **+0.089**、幻觉率 **−0.024**
  - 单题成本 **~$0.05**、端到端 **~4.7 min**(5 题基准集)
- **v2 命题**:把已验证的研究引擎包一层面向用户的产品(会话、存储、可读报告、溯源面板),验证「深度研究」作为独立产品形态的用户价值。

## 3. 目标与成功指标

**业务目标**:验证深度研究产品的用户价值——用户愿意等 ~5 分钟拿一份可信报告,并且会重复使用。

| 类型 | 指标 | 目标 |
|---|---|---|
| 北极星 | 周被采纳报告数(被导出或保存) | v2.0 上线后逐周上升 |
| 参与 | 研究完成率(发起 → 产出) | ≥ 85% |
| 差异化验证 | 报告引用点开率 | ≥ 30%(验证「可溯源」是否真被使用) |
| 留存 | W1 → W2 复用率 | ≥ 25% |
| 成本/质量护栏 | 单题成本 / 时长 / Grounding | ≤ $0.10 · ≤ 6 min · ≥ 0.90 不回退 |

## 4. 目标用户与核心场景

**画像**:行业分析师 / 咨询顾问 / 投研人员。共同特征:产出物要交付(给客户或领导),对来源可信度极敏感,时间按小时计机会成本。

**核心场景(user story)**:

> 作为竞品分析师,我想输入「对比 X 与 Y 的适用场景与工程权衡」这类问题,10 分钟内拿到一份结构化报告——每条结论都能点开看到来源原文与验证状态——以便直接引用进周报,不再花半天人工核对来源。

## 5. 功能需求

### P0(v2.0 必须)

| # | 功能 | 说明 | 验收标准 |
|---|---|---|---|
| F1 | 问题输入与引导 | 输入框 + 预设示例问题一键填入 + 问题类型提示 | 新用户 30 秒内能发起第一次研究 |
| F2 | 编排过程实时透明 | 时间线:规划 → 并行检索 → 验证 → 撰写,各阶段状态与进度实时滚动 | 任意时刻可见当前阶段、已检索来源数、已耗时 |
| F3 | 报告阅读 | 结构化渲染,事实性陈述带 [n] 引用标注 | 100% 事实性陈述有引用编号 |
| F4 | 可溯源验证面板(核心差异化) | 点开任一结论:来源原文摘录 + 验证状态(supported / weak / unsupported) | 100% 结论条目可点开查看验证状态 |
| F5 | 历史研究库 | 研究列表、报告回看、过程回放(trace) | 完成的研究 30 天内可回看与回放 |

### P1(v2.x 迭代)

| # | 功能 | 说明 |
|---|---|---|
| F6 | 报告导出 | Markdown / PDF / Word |
| F7 | 异步队列与通知 | 研究完成后通知,无需驻留等待 |
| F8 | 基于报告追问 | 追问触发定向补检索,增量更新报告 |
| F9 | 成本与用时透明 | 每次研究展示 token 用量与成本 |

## 6. Non-goals(v2 明确不做)

- **协作 / 多人编辑 / 团队空间**——B 端前置能力,单用户价值未验证前不投入
- **订阅式主题监测**——依赖历史库与重复研究行为先成型
- **通用聊天助手模式**——与「深度研究」定位冲突,稀释差异化
- **移动端**——报告阅读与溯源面板是大屏场景

## 7. 风险与开放问题

**风险:等待流失。** 端到端 ~4.7 min,远超网页常规容忍度。缓解:F2 把等待转化为「可观察的研究过程」——进度感本身是产品价值(这是 v2 保留实时时间线的产品理由,而非纯技术演示)。

**风险:搜索源质量依赖第三方。** 检索上限受搜索 API 制约;来源数量护栏与失败重试已在 MVP harness 覆盖,多源冗余列入 v2.1 评估。

**开放问题**:

- ~~weak / unsupported 的结论条目如何呈现:静默删除 vs 显式标注保留?~~ **已决策(原型阶段)**:显式标注保留——静默删除与「可信度」定位冲突(等于黑箱);采用三色验证徽章(supported / weak / unsupported)+ weak 附「建议人工复核」提示,unsupported 折叠置底。
- 时长 > 8 min 的研究:降级先出草稿,还是允许继续?(仍开放)

## 8. Roadmap

v2.0(P0 全量,~6 周)→ v2.1(F6 导出 + F7 异步通知)→ v2.2(F8 追问与增量研究)
