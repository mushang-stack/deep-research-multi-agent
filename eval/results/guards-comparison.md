## 3. 发现(本实验的真实产出)

**F1 · run 池是成本上限,不是节省机制——其价格是完成率。** off 侧单题自然花费分布 151k–447k。400k 切在分布带正中:q002 在完成 94% 时(421k vs 自然 447k)被杀,q004 因该轮轨迹偏贵(405k > off 的 267k)被杀。护栏正确执行了"上限"语义:被杀题的花费被精确帽在池值附近(熔断消息 `421369/400000` 即诚实计数的现场证据)。

**F2 · 单题花费的 run 间方差 ±2×,单值阈值天然脆弱。** q001:151k→346k→375k;q005:423k→231k→301k;q004:267k→405k(死)→519k(活)。温度 0.3 下轨迹方差远大于题间差异——任何落在 300–450k 带内的池值都会随机误杀;700k(观测最大 +57% 余量)仍死于 q002 该轮轨迹膨胀到 721k。

**F3 · 预算护栏与缺口驱动编排存在互噬。** q002 的 700k 轮:子 agent 产出变薄(该轮多 researcher 不收敛,同 q003 模式)→ orchestrator 缺口驱动加派检索轮 → 总花费反升至超过 off 自然值 62% → 池死。紧预算在"补一轮试试"的编排器上可能**增加**总花费——直到池把它杀掉。这正是 run 池存在的理由,但也说明它的正确用法是"灾难保险丝"而非"日常调节旋钮"。

**F4 · researcher 步数不收敛是比预算更深的问题,且随机复发。** on-700k 的 q003:12/12 researcher 全部撞 6 步上限、0 findings → `no_report` 兜底(M3 健壮性路径正常工作,单题净损失 $0.044)。而 on-400k **同配置**下 q003 全部收敛、35 findings。M2 时代的收敛问题在温度 0.3 下以轨迹级概率复发,与护栏无关;护栏的价值是把这类发散的损失上限从"无界"钉在池值。

**F5 · P2 压缩与 partial 本题集零触发。** researcher 单轮 prompt 全程 < 30k 阈值、单体花费(off 均值 ~26k)<< 60k 预算——30k/60k 对 64k 窗口 + 本题集是宽安全阈。二者的正确性由 29 个新增单测背书(含 tool_call_id 配对、幂等、恰好一次收尾等契约),现场证据留待更长任务。

## 4. 结论与推荐姿势

- **机制验收 ✓**:检测/计数/熔断/escalation/容错全部按设计工作;完成题质量不倒退;丢失题花费被帽住。
- **经济性验收 ✗(按设计如此)**:护栏不省钱,只封顶;spec §9 "长任务 token 可见下降"在本题集不成立(题太短,压缩够不着触发区)。
- **代码按 spec §9 以默认关闭合入**(278 测试零行为扰动);启用建议:
  - run 池仅作灾难保险丝,余量 ≥ 2× 观测最大单题花费(本题集 ≥ 900k),接受"极少数题被杀"换"单题成本上界确定";
  - researcher 预算取观测分布的 p95(本题集 ~40k,60k 已安全);
  - 压缩 30k 阈值已验证安全,长任务(n>10 轮)场景是其价值区;
  - 真正的下一步是 researcher 收敛稳定性(F4),那是 prompt/步数预算层的事,不是 token 预算能解的。
